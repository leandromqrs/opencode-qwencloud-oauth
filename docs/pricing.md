# Model pricing metadata

The plugin publishes representable QwenCloud management-catalog tariffs in OpenCode's native model costs. These are USD API reference tariffs, not evidence of actual cash charges under the Token Plan subscription, remaining quota, or inference entitlement. Actual invoices and subscription terms remain authoritative.

## Source contract

The public official CLI source was inspected at commit [`264999e87d2fe819a9c570a9f3cbc1c9864a5163`](https://github.com/QwenCloud/qwencloud-cli/tree/264999e87d2fe819a9c570a9f3cbc1c9864a5163):

- [`src/types/api-models.ts`](https://github.com/QwenCloud/qwencloud-cli/blob/264999e87d2fe819a9c570a9f3cbc1c9864a5163/src/types/api-models.ts) defines model `Prices` and `MultiPrices`. Each price has string `Type`, `PriceUnit`, `Price`, `PriceName`, and optional string `Discount`. A multi-price range has `RangeName` and `Prices`. Built-in-tool prices are separate and are not mapped to token costs.
- [`src/site.ts`](https://github.com/QwenCloud/qwencloud-cli/blob/264999e87d2fe819a9c570a9f3cbc1c9864a5163/src/site.ts) fixes the QwenCloud site's currency to USD. Model price items do not declare a separate currency field. The plugin accepts the evidenced units `USD/1M tokens` and `Per 1M tokens` for this site, rejects other units, and rejects an unexpected explicit non-USD currency.
- [`src/api/model-mapper/pricing-taxonomy.ts`](https://github.com/QwenCloud/qwencloud-cli/blob/264999e87d2fe819a9c570a9f3cbc1c9864a5163/src/api/model-mapper/pricing-taxonomy.ts) provides the exact price-type names. [`pricing-mapper.ts`](https://github.com/QwenCloud/qwencloud-cli/blob/264999e87d2fe819a9c570a9f3cbc1c9864a5163/src/api/model-mapper/pricing-mapper.ts) gives recognizable ranges precedence over flat prices, assigns repeated types in published order, and chooses explicit cache reads before text/implicit cache alternatives.
- [`src/api/model-mapper/pricing-summary.ts`](https://github.com/QwenCloud/qwencloud-cli/blob/264999e87d2fe819a9c570a9f3cbc1c9864a5163/src/api/model-mapper/pricing-summary.ts) applies discount multipliers only in `(0, 1]`, rounding discounted prices to ten significant digits. The plugin follows this discount policy but does not copy permissive numeric-prefix parsing, invalid-to-zero conversion, cheapest-price summaries, or removal of explicit zero.

The installed OpenCode 2.2.5 schema, `@opencode/schema/dist/model.js`, requires `input`, `output`, `cache.read`, and `cache.write` as finite USD-per-million-token values. Its only tier discriminator is an optional `{ type: "context", size }`; it cannot describe per-second/image/character pricing, modality-specific token prices, or arbitrary named modes.

The official runtime also treats null discounts as absent, tolerates missing/null labels with a price-type fallback, and accepts finite numeric discounts through JavaScript numeric parsing. Sanitization normalizes these harmless representation differences without accepting numeric price prefixes or changing the monetary validation rules. Null price/range collections mean absent collections.

## User-approved display and estimation policies

The user explicitly chose to show pricing with cache estimates. Only a genuinely absent cache-read or cache-write price is estimated at that tier's ordinary input-token rate. Each component is handled independently. An explicit advertised zero remains zero. An invalid or unsupported explicit cache price makes the native cost unavailable instead of being replaced by an estimate.

Estimated cache rates are not advertised cache tariffs. Native model costs cannot label individual components as estimated, so the catalog RPC's existing `pricing` description identifies this policy. Session cost calculations involving estimated cache rates are estimates, not billing statements. Original sanitized price items retain only source data; fallback rates are generated during native projection and are never written into those items.

The user subsequently chose to follow the CLI's display selection: the last published entry for an identical `Type` wins, and cache reads prefer `input_token_cache_read`, then `text_input_token_cache`, then `input_token_cache`. These explicit and implicit cache tariffs are distinct billing modes, not aliases. Applying the CLI's display priority to OpenCode's single cache-read cost does not prove which mode was charged for a request. Similarly, repeated types may have conditions such as `TimeBand`, which the native cost schema cannot represent; retaining published order and following the selected display policy is not a claim about actual time-dependent billing. Neither the cheapest nor the most expensive price is inferred. Source items retain their order, and selection happens only during native projection.

## Conservative projection

Ordinary input prefers `input_token` over `text_input_token`; ordinary output prefers `output_token` over `purein_text_output_token`, following the CLI's ordinary-text selection without treating explicit zero as absent. Cache-read priority is described above; cache writes use `input_token_cache_creation_5m`. All relevant ordinary/cache entries must have valid numeric values and token units, including repeated or lower-priority entries: a malformed advertised price is never silently discarded in favor of another entry or an estimate.

Clearly distinct `input_token_batch`, `output_token_batch`, `thinking_input_token_batch`, and `thinking_output_token_batch` alternatives are excluded from synchronous pricing rather than invalidating complete synchronous tariffs. Unknown, non-batch thinking, audio, vision, embedding, or non-token price types still make the combined price list unsupported rather than being summed into ordinary chat tariffs.

Actual malformed or unrepresentable ranges never fall back to flat prices. A separately authorized pricing-only observation on 2026-11-12 established one exact empty backend placeholder: `MultiPrices: [{ Prices: [{}] }]`, with no other fields on the range or price item. Like the CLI's recognizability check, the plugin treats only this exact placeholder as absent so valid flat prices remain usable. Adding a range label, a price field, an unknown field, another item, or another range prevents this exception; malformed advertised cache prices cannot disappear through it.

Supported context labels use explicit integer bounds, such as `0-128000` followed by `128000-256000`, or the observed inequalities `Input<=256k` followed by `256k<Input<=1m`. A three-range example is `Input<=32k`, `32k<Input<=128k`, `128k<Input<=256k`. Decimal multipliers are `k = 1000` and `m = 1000000`, consistent with the observed `1m` endpoint and declared `ContextWindow: 1000000`. Resulting bounds must be safe integers within the catalog's token limit, ascending and contiguous from zero. Named modes, gapped/overlapping ranges, alternative inclusivity, and image-volume ranges are not inferred. The model must have a known context limit no greater than the final range endpoint, because native tiers cannot encode an upper bound.

OpenCode's current upstream [`packages/core/src/session/usage.ts`](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/usage.ts) selects the largest context threshold strictly below actual context, falling back to the tierless base. The plugin therefore maps each subsequent explicit range's lower bound to `tier.size`. The installed plugin schema was verified locally; the core selection behavior was inspected in current upstream documentation rather than installed core source.

Prices must be complete finite nonnegative decimal strings; numeric junk, negative prices, overflow and underflow are not converted into zero. Invalid discounts leave the base tariff unchanged. Sanitization allows at most 64 items per list, 32 ranges, and 256 total items per model, with bounded strings and no control characters. Malformed or oversized metadata is retained only as an invalid-pricing marker, so cached restoration cannot accidentally turn a malformed advertised cache price into an absent-cache estimate. Unrelated payload fields are discarded.

Unsupported billing metadata stays available as sanitized source metadata but produces no native token cost. Examples from the official contract include Wan video rates per second, image-generation rates per image, speech rates per character or duration, and mode-specific Omni rates. Their absence from native costs must not be read as free pricing.

## Cache compatibility and verification

Existing version-2 account-bound caches remain valid. Old entries without pricing, or entries already reduced to an invalid-pricing marker by an older sanitizer, stay unknown until an explicitly requested catalog refresh retrieves price data. An invalid marker contains no prices to reconstruct. No automatic refresh, cache mutation interface, replay override or cache migration is introduced. Account partitioning, denial tombstones, source-connection fencing, model IDs, names, limits and capabilities are unchanged.

Focused synthetic tests cover source-to-cache-to-native projection, the actual native schema, zero and missing values, cache estimation, display precedence, repeated types, discounts, malformed values, the exact empty placeholder, ranges and bounds. A plugin refresh test checks published native costs and unchanged key/account fencing. Two separately authorized catalog observations established real payload compatibility; the temporary pricing-only diagnostic hook was removed afterward. No inference, generation, purchase or key change was needed to establish pricing metadata.

The separately authorized final reload and catalog refresh on 2026-11-12 published 186 native models, of which 57 had representable native costs. The catalog contained 181 pricing records; two remained invalid under the bounded sanitizer. Missing, malformed, or unsupported metadata continues to produce no native cost, never a fabricated zero. The temporary probe's stale compiled artifacts were also removed.

Live native inventory assertions confirmed input/output USD per million tokens of `2 / 6` for Qwen3.8 Max, `0.15 / 0.47` for Qwen3.8 Flash, and `0.3 / 1.2` for DeepSeek V4.1 Flash 1017. Qwen3.7 Plus published `0.32 / 1.28` through 256,000 context and `0.96 / 3.84` above that threshold. Wan3.0 Video correctly retained no native token cost. These observations verify reference-price publication under the policies above, not actual request billing.

Final validation passed all 136 tests with none skipped, TypeScript typecheck, build, and whitespace checks. A temporary inversion of batch filtering caused the pricing tests to fail and was restored before final validation. No generation, purchase, credential replacement, commit, or push was performed for this pricing change.
